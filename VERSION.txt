--------------------------------------------------------------------------------
本版核心：KV 记忆（KV archive + retrieval recall）
--------------------------------------------------------------------------------

长上下文里被滑出显存的 KV 页不再丢弃：先归档到主机内存；prompt 读完后用最后一个
query 给所有归档页打分，挑出最相关的一段连续页换回显存，再重放最后一个 chunk。
目标：长文里"答案在深处"的场景，从答不出来变成答得对。

启动参数（新增四个，不传则行为与 pre-r7 完全一致）
  --resident-tokens N   常驻窗口 token 数            默认 20480
  --sink-tokens N       attention sink token 数      默认 2048
  --archive-mib N       主机侧归档 arena（MiB）        默认 2048；给这个参数自动开归档
  --kv-retrieval 1      打开检索召回                   默认 0（关）

  等价环境变量：NINFER_RESIDENT_TOKENS / NINFER_SINK_TOKENS /
                NINFER_KV_ARCHIVE_MIB（自动置 NINFER_KV_ARCHIVE=1）/ NINFER_KV_RETRIEVE
  调优：NINFER_KV_RECALL_PAGES(112) / NINFER_KV_RECALL_BACKOFF(56) / NINFER_KV_REPLAY(1)

推荐（96K 以上长文，问题在末尾）
  --kv rk4v4-e8 --ctx 262144 --resident-tokens 20480 --sink-tokens 2048 \
  --archive-mib 4096 --kv-retrieval 1

实测（96K 正文，needle 埋 25/50/75/92% 深度）
  25% / 50% / 75%：检索关 = miss，检索开 = HIT（口令逐字符命中）
  92%           ：两种情况都 HIT，且输出逐 token 相同（无回归）
  归档开销      ：prefill 801.997 → 800.446，decode 33.14 → 33.62（噪声内），输出逐 token 相同
  GATE 回归     ：8k 35.63/931.4 · 96k 24.90/422.1 · mtp 80.21/842.2（检索默认关闭，无回退）

限制（务必先读）
  召回是启发式：页均值打分定位误差约 ±8 页，取 112 页连续段兜住
  必须读完 prompt 才能召回（query 取最后一个 token）；问题不在末尾没有保证
  额外显存：页摘要 ~168 MB（1311 页）+ 环形缓冲 64 MB；主机内存：最多 --archive-mib
  只在 needle 语料上验证过（多跳推理、整篇摘要无数据）
  详见 docs/KVMEM.md

本版核心结论（务必先读）
  --ctx 必须 = prompt + max_new，一个 token 都别多开
    126K 语料：--ctx 131072 → 10.12 t/s；--ctx 126464 → 22.91 t/s（2.26x）
  根因：KV 池按 --ctx 一次性全量提交（int4 17920 B/token），越过 Windows 驻留预算
        （约 12.6~13.6 GiB，当天漂移 ~1 GiB）后整池降级到系统内存，走 PCIe ~30 GB/s
  开了 --resident-tokens 窗口模式后，驻留量由窗口决定，不受这条约束

推荐配置（按真实上下文选）
  真实 <=8K      : --ctx 16384  --kv rk4v4-e8 --spec mtp --draft-tokens 2  -> 77.8 t/s
  真实 16-32K    : --ctx 32768  --spec mtp --draft-tokens 2                 -> 64.5 t/s
  真实 48K       : --ctx 49152  --spec mtp --draft-tokens 2                 -> 34.9 t/s
  真实 64K       : --ctx 65536  （AR 28.4 / 加 MTP 34.9）
  真实 96K       : --ctx 98304  --spec mtp --draft-tokens 2                 -> 34.0 t/s
  真实 126K      : --ctx 126464 （必须关 MTP）                              -> 22.9 t/s
  长文 + KV 记忆 : --ctx 262144 --resident-tokens 20480 --sink-tokens 2048
                   --archive-mib 4096 --kv-retrieval 1

未修（见 docs/PATCHLIST.md 末节）
  多模态（图像输入）：本版 harness 无入口（artifact 有 vision、引擎有 enable_vision 通路）
  int8 KV 非确定性 · fp8 KV 的 QK 是 __builtin_trap() 桩 · dflash2 坏路径
  126K 以上 MTP（差 0.5 GB 预算）· prefill >=64K 落后 llama · 256K 需 KV offload
  短上下文 45 t/s 未达（AR 37.3，物理上限 54）

重要用法
  --ctx 必须贴近实际 prompt 长度（126K：ctx126464 → 22.9；ctx131072 → 10.1）
  MTP 只用 --draft-tokens 2；>=100K 真实上下文关 MTP
  引擎 exe 裸双击需要 ROCm DLL 在 PATH：chat.bat 已自动补

安全铁律
  绝不对卡在 GPU 上的引擎进程 Stop-Process（会让 GPU 队列永久卡死 → 黑屏硬复位）
  不要跑 --no-graph + NINFER_PROFILE_* + --spec mtp 组合
  扫测进行中禁止编译/链接（构建会 taskkill 引擎进程并改写 exe）
